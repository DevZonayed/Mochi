# Mochi 0.5.0 — "Proven, not rendered"

**Date:** 2026-06-07
**Status:** Approved (Option A — full scope), in implementation
**Source:** Post-mortem proposal `RGV Compliance web-portal QA` (see `.context/attachments/.../pasted_text_2026-06-07_08-22-34.txt`)

## Problem

A browser-QA engagement repeatedly declared work "verified" when it wasn't:
false "zero console errors" (read from a stale buffer), dead buttons reported as
working (presence mistaken for function), writes never checked for persistence,
and a stale cached JS bundle that misled both agent and user. The throughline:
**optimized for "looks done" instead of "proven done," with no enforced coverage
gate.**

## Goal

Make "it works" a *measured* claim. Three layers:
1. **Trustworthy observation primitives** (browser MCP) — so an action's effect
   can be proven, not inferred.
2. **A coverage-driven QA loop that cannot lie** (the honesty gate).
3. **Memory that remembers what was actually verified** and never asserts stale
   facts.

## Architecture

Two tool classes in `server/src/tools.js`: **wire tools** (in `TOOL_TO_WS_TYPE`,
dispatched to the extension via the broker) and **local/server tools** (handled
in `handleToolCall`, composing other calls). DOM/CDP-native capabilities go
extension-side; pure orchestration stays server-side.

### Browser MCP (server + extension)
- **Console/network truth** — per-tab nav epoch (`lastNavAt`, stamped by
  `navigate()` + `Page.frameNavigated` main frame); `console_messages` and
  `network_requests` gain `sinceNavigation`; `network_requests` auto-captures
  response bodies for `>=400`/failed (CDP `getResponseBody` on `loadingFinished`).
- **`browser_assert_no_errors`** (server composition) — fails if any console
  error/exception or `>=400`/failed request since the page loaded.
- **`browser_audit_interactives`** (extension) — every actionable element +
  `{selector, role, accessibleName, visible, inViewport, disabled, hasClickHandler}`.
- **`browser_act_and_observe`** (server composition) — performs an action,
  returns `{networkDelta, consoleDelta, urlChanged, domChanged, classification}`
  ∈ {WORKS, NO-OP, ERROR, NAVIGATES}.
- **`browser_wait_for_response`** (extension, event-driven; checks buffer first).
- **`browser_page_assets`** (extension; in-page SHA-256 so same-origin creds apply).
- **`browser_set_storage`** (extension; localStorage/sessionStorage via injected
  script, cookies via CDP `Network.setCookie`).
- **Enhancements** — `navigate {hardReload, disableCache}`; `click` disabled
  detection + one transient-not-found retry; `session_health {heal}` re-attaches
  the debugger; docs clarify `emulate_viewport` (JS layout) vs `window_resize`.

### Exhaustive QA mode + honesty gate (`plugins/qa`)
`/qa exhaustive` runs inventory (routes × roles × breakpoints → audit) → verify
each control (act_and_observe → classify with evidence) → prove writes persist →
unhappy paths → **honesty gate**: `plugins/qa/lib/qa_coverage.js` computes
coverage from the ledger and **exits non-zero while any cell is UNTESTED/
UNCERTAIN** — a "pass" verdict is un-fakeable. Output is a coverage table + an
explicit "Did NOT verify / why" list. Default phrasing: "N of M controls
verified — here's each result, and here's what I couldn't verify."

### Memory (`plugins/continuum`)
- **Verification Ledger** — `.continuum/verification/<slug>.json` (zero-dep JSON,
  schema per §6.1 of the proposal) + `lib/verification_ledger.js` (+ CLI):
  write/merge/coverage/diff; re-test only deltas since `bundle_hash`.
- **Provenance** — link `meta.json` gains `bundle_hash` + `plugin_version`;
  SessionStart writes `.continuum/.env-provenance.json`.
- **Verify-before-assert** — `recall` flags stale hits (age); SessionStart
  injects a verify-before-assert + gotchas reminder.
- **Tooling gotchas** — canonical `skills/browser/references/gotchas.md`,
  surfaced at SessionStart.

## Non-goals
- Embedding-based recall (still stemmed-token; deferred).
- Chrome Web Store publication of the extension.
- Reworking playbooks/workflows.
